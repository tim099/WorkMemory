Tim 2026-08-11 一天內六次換框架，全部是「挪掉前提」不是「調參數」。逐條記下，因為
它們是 v3 流程的成因：

1. 條件太多會掉細節 → 不是調約束，是**改用參考圖**（世界交給圖，prompt 只放會被違反的）
2. 人設圖做三視圖 → 不是加提醒，是**修上游**（人設圖是所有頁面的來源，帶標註會被學走）
3. 文字放 .md → 不是規範字怎麼畫，是**讓畫面不必有字**（一次解掉語言/滲漏/prompt 過載）
4. 先別重修已完成的 → 不是套用新流程，是**驗證新流程**（回到 Stage 3 試畫）
5. 分鏡列 props → 不是要求記得看設定，是**讓清單出現在必經的路上**（frontmatter 開畫第一秒讀到）
6. 文件不留歷史 → 不是精簡，是**沿革由 git 承載**，文件只寫現在該怎麼做

共同形狀：**把辨識工作從記憶轉移出去。** 不是提醒，是讓判斷變成一個動作。
