# stt_prompt 是雙面刃 —— 三格 A/B（同一場、同一機器、同一部片，2026-08-11 實測）

| | 長清單（92 字） | 短版 `アシタカ、サン` | 空 |
|---|---|---|---|
| **prompt 回吐** | 整份清單＋繞回一輪 | 短版（**假得像真台詞**） | **0 筆** |
| **片假名漂移** | 有 | 整句化 | **消失** |
| **專有名詞** | 無乾淨證據 | 已開始退化 | **全面退化** |

## 機制
`initial_prompt` 的語意是「這段音訊之前的文字」，whisper **接著它往下寫**。
餵逗號分隔的名詞清單 → 對它來說「前文是一份名單」→ **無台詞段就繼續列名單**。
**跟長度無關**：縮短只讓 payload 變短，而**短版更難識破**
（`アシタカ、サン` 完全長得像一句真台詞，劇裡真有人喊這兩個名字）。

## 反直覺結論
**這個旋鈕不該轉。** 兩端各有一種病：
- prompt ON → 回吐 + 漂移 → **可以用過濾治**
- prompt OFF → 名詞全面退化 → **過濾治不了**（那不是多出來的東西，是少掉的）

## 正解組合
```
留 prompt（覆蓋名詞）
＋ per-segment 有序子序列過濾（擋回吐）
＋ prompt 寫成「漢字混寫的自然句」而非片假名名詞列（同時治漂移）
```
第三項**未實測**，是推論。

## 過濾判準演化（我當天改了三次，前兩版作廢）
1. ~~重疊率 ≥60% 就丟~~ → **會誤殺真台詞**（劇裡真有「アシタカ！サン！」）
2. ~~輸出是 prompt 的**有序**前綴/子序列 → 丟~~ → 判準對了（順序是回吐的指紋，重疊率只是影子）
3. **最終版：判準同 ②，但作用域必須 per-segment，不是 per-chunk。**
   血證：21:27:50 真台詞 `最初の者を殺す!` 與幻聽 `3日` **同一秒**；
   21:35:28 真台詞夾在 `3,2,1,2,1…` 數字串中間。**同一 chunk 內真假共存。**
