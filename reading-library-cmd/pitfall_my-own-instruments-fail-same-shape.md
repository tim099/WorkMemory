**2026-09-15 一天之內，我自己造的量具用「它要防的那個形狀」壞掉四次。**

| # | 量具 | 它怎麼壞 | 抓到它的是什麼 |
|---|---|---|---|
| ① | 我加的「Fixes 沒頂格要出聲」警告 | python 寫 C# 時 `\b` 被解成**退格字元 0x08** ⇒ regex 永遠不命中 ⇒ **那道警告自己是靜默的** | 我在 clean-room 重跑一次、發現零輸出 |
| ② | 驗章檔身分的第二把尺 | 拿章裡的**本地** `HH:mm` 比訊息 `ts` 的 **UTC** 時分 ⇒ **40/40 全紅** | 讀數裡有「同一個人差兩分鐘」的格 —— 那個形狀在喊「是尺不對」 |
| ③ | 走棋帶的 `--say` | 句子含空白，穿過 `step_args` 被 tokenizer 切碎 ⇒ 整步 exit 2 | 工具自己的 usage 行 |
| ④ | 寫見叢的 `--arg add="…"` | 文字含**反引號** ⇒ **bash 當成指令替換執行** ⇒ 落盤的那行變成「確認 🔢 exit_code = 2 的…」 | 回讀 `_keys_open.md` |

📌 一般形：**一個永遠不會觸發的警告，跟一個沒有寫的警告，在輸出上完全一樣。**
⇒ 而 ③④ 同一族（**文字穿過 shell／參數層**），規矩早就寫著「長文一律 `--arg-file`，不經過 shell」——
🩸 ④ 是我**在寫這條教訓的那一行上**違反它。

**可操作的修法（⛔ 不是「更小心」）**：
1. 新加的守衛要**先讓它紅一次**：把被測的東西拿掉，看它會不會變紅。沒紅過的守衛＝沒有讀數。
2. 任何帶空白／標點／反引號的文字，**一律 `--arg-file`**，無例外。
3. 用 python 寫 C#／regex 時，`\b` `\n` `\t` 這族**先用 bytes 回讀確認**，⛔ 不信「我寫的是雙反斜線」。
