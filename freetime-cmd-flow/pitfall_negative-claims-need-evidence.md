# 「完全未開始」是一個我從沒查過的斷言

## 現場

2026-08-18，我把自由時間這條線交接給 @gura，第一項待辦寫的是
**「`UCL_FreeTimeAdminPage` 完全還沒開始」**。

它早就存在：`UCL_EditorMenuPages/UCL_FreeTimeAdminPage.cs` **422 行**、
規格文件 `Docs~/{lang}/UCL_EditorPage/UCL_FreeTimeAdminPage.md` **92 行**。

我在**四則訊息**裡反覆宣稱它不存在（「完全沒開始」「仍未開始」「完全還沒開始」），
還寫進工作記憶交接檔與酒館公告。**期間一次都沒有跑過 `ls` 或 `find`。**

## 為什麼會發生

Tim 說的是「`UCL_FreeTimeAdminPage` 另外有需要的話 可以重構活動相關資料結構」——
他在**指一個既有的頁**。而我把它讀成「請你建一個」，因為前一則他才要我
「參考 `UCL_ProcessAdminPage` 做一個對應 `UCL_SessionService` 的管理頁」（那個確實不存在，我建了）。

⇒ 兩個相鄰的指令，一個是「建新頁」、一個是「改既有頁」，**我把第二個當成第一個的延續**。
而一旦進入「這是我的待辦」這個框，那件事就不再是「需要查的事實」了 —— 它變成前提。

## 這隻的形狀（跟今天另外三隻同族）

今天我抓到三隻「每一層都在說真話，而真話拼起來指向錯的地方」：
bool 靜默字串化、`op=pick` 沒指向 `op=step`、引號被 CreateProcess 吃掉。

**這第四隻不一樣，而且更難防**：那三隻是機制騙了我，這隻**沒有任何一層在騙我** ——
檔案一直在那裡，`ls` 一次就會看到。**是我沒有問。**

⚠ 而它躲過了我所有的自省機制：
- 「編過不等於抵達」防不到 —— 我根本沒寫 code
- 「去讀產物」防不到 —— 我沒有產物可讀，因為我以為要從零做
- 「⚠ 標記未驗」防不到 —— 我確實標了「未開始」，而那個標記本身就是錯的內容

⇒ **「不存在」跟「已完成」是對稱的兩個斷言，而我只對後者設了防線。**
我對「✅ 完成」會要求證據，對「⚪ 沒有」卻直接採信自己。

## 修法（動作型，不是提醒型）

**交接／回報清單裡每一個「不存在／未開始／沒有人做」的項目，寫下之前先 `ls` 或 `find` 一次。**
成本是一行指令，而漏掉的代價是**讓接手的人去重建一個已經存在的東西** ——
那不只浪費她的時間，還會產生第二份實作，然後兩份漂移。

判準一句話：**否定句也是宣稱，也要有讀數。**
