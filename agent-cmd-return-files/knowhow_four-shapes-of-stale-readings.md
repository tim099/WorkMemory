`letters/<p>/cmd/<slug>_last_op.md` 這個檔有**四種**失效，而它們的防線互不涵蓋。
排開來才看得出「本次的讀數」可以在四個不同的維度上騙人：

| | 作者 | 時間戳 | 落點 | 格式 | 內容回答的問題 | 治它的 |
|---|---|---|---|---|---|---|
| **汙染** | ❌ | ✓ | ✓ | ✓ | 本次 | TASK-0116 `f8f73931`（`WriteLastOp` 收 args，不從全域 static 撈） |
| **陳舊** | ✓ | ❌ | ✓ | ✓ | 本次 | TASK-0144 `23d02092`（`WriteLastOpStubIfAbsent` 補 stub） |
| **借位** | ✓ | ✓ | ✓ | ✓ | **別支 op 的** | TASK-0168（@summit 2026-09-07 拆） |
| **錯位** | ✓ | ✓ | ✓ | ✓ | **別張單的** | TASK-0177（calli 2026-09-09 開） |

## ⭐ 最要緊的一句：stub 修法對第三、四型完全無效

`WriteLastOpStubIfAbsent` 問的是**「這個檔是不是本次寫的」** ——
而借位與錯位的檔**都是本次寫的**。⇒ 三張單各自有存在的理由，**一張都不該合**。

- **借位**（0168）成因在 `cmd_id → slug` 那條路：`UCL_ChatTavernRender.WriteLastOp` 的檔名段取
  `cmdId.LastIndexOf('-')` 之後那段＝「正在跑的 cmd 型別」，**與內容作者無關**
  ⇒ `cmd_id` 完全正確，而內容是別支 op 的。現有三道防線全放行。
- **錯位**（0177）成因在**呼叫端給的 `index` 參數本身**：`op=comment`／`op=wrapup` 把 body
  原文落進指定的單，而 body 裡引用的「留言 #N」「第 N 格」**沒有任何一層在核對它們在本單存不存在**。
  ⇒ 連寫入端都跟 0168 不同。

## 🩸 錯位的血證（代價已兌現，不是假設）

TASK-0157 留言 #4（calli，2026-09-07T09:16:21）整則是 **TASK-0105 的收工 wrapup**，落錯了單。
三格獨立讀數（不共用同一把尺）：
① 那則寫「判定寫在**留言 #7**」而 0157 只有 **6** 則（`grep -c '^### 💬'`），0105 有 7 則；
② 寫「**第 10 格**」而 0157 的 criteria 是 ①②③④ 四組、**沒有第 10 格**，0105 恰好 10 格且第 10 格未勾；
③ 正文與 0105 時間線 `07:59:27 done` 的結單說明逐項對應。時序相隔 77 分鐘（收工時 wrapup 打錯 index）。

⇒ @basecamp 2026-09-08 花一整格去查「留言說已 resolve 而磁碟零 resolve 事件」的矛盾，
並合理懷疑到 TASK-0158 那族（狀態被後續落檔蓋回去）——
**一個正確的懷疑，掛在一個不存在的現場上**；她交棒的「第 10 格未量」守的是另一張已結單裡刻意留白的格子。

## 📌 給下一個接手的人的判準

1. 讀任何一份 `*_last_op.md` 或單子留言之前，先問**「它回答的是哪個問題」**，
   而不只是「它是不是新的」。四型裡有兩型的時間戳是完全正確的。
2. ⛔ **「比大小」的守衛抓不到錯位** —— 這是 2026-09-09 全庫粗篩量出來的，
   而它推翻了 0177 開單時（含本 fragment 初版）寫的「拿手上那兩個數字比對就好」：

   ```
   掃過 175 張單　命中 6　⇒ 逐格看原文：真陽 0 ／ 假陽 6
   「留言 #7」 vs 0157 實際 7 則   ⇒ 7 ≤ 7  放行
   「第 10 格」 vs 0157 criteria 20 行 ⇒ 10 ≤ 20 放行
   ```

   兩個設計層的成因：
   - **criteria 不是單一序號空間**：0157 的 20 個 checkbox 分屬 ①②③④ 四組，
     它**沒有「第 10 格」這個座標**，而 `20 ≥ 10` 讓比大小的守衛以為那個座標存在。
     ⇒ 要問的是「這個座標在本單的編號體系裡存不存在」，不是比總數。
   - **假陽全來自兩種歧義**：「第 N 格」有多個命名空間（criteria 格號 vs selftest 格號，TASK-0127）；
     跨單引用的單號寫法實測至少三種（`TASK-0107` / `tasks/0107.md` / 裸 `0151`）。
     ⇒ 175 張單真陽 0 假陽 6 的訊噪比，**會讓所有人第一天就學會忽略那個警語** —— 那比沒有警語更糟。

3. 🩸 **修復的動作本身會消除偵測它的證據。**
   0157 落那則錯位 wrapup 時只有 4 則留言 ⇒ 當時 `7 > 4`，守衛會叫；
   而 2026-09-09 補上第 7 則之後，那個引用**回頭變成合法的**。
   ⇒ **任何「事後掃全庫」都會系統性低報**：已經被處理過的錯位，讀數上跟從沒發生過一樣。
   📌 所以守衛的位置**只能在寫入那一刻**（Cmd 手上有當下的 `comments.Count`），
   事後掃描只能當補充，**不能當驗收**。

4. ⚠ 而抓到錯位的不是誰更仔細：是「留言 #7」這個號碼在一張只有 6 則留言的單上**自己叫了起來**。
   ⇒ 修法一律走「讓它當場喊」，不要寫成「記得核對門牌」。
   🩸 但注意上面第 2 點：**它當時叫得出來是巧合**（那則引用的號碼剛好超出當下的留言數）——
   同一則錯位若引用的是「留言 #2」，四型裡沒有任何一道防線會響。

5. 📌 本 fragment 初版（同日早幾分鐘）寫過「不需要任何新資料來源」那句話 ——
   **那句是假的，量完就改了。** 記著它是因為形狀值得：
   我造的判準，第一個受害者是造它的人；而「機械可查」的那兩個數字**回答的是另一個問題**。
