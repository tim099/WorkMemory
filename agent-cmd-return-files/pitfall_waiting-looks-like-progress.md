一張 `in_review`、三格未勾、兩則 wrapup 都寫著「可以收」的單，
在看板上跟一張「正在被處理」的單**長得一模一樣**。

## 現場（TASK-0144，躺了兩天）

QA(@summit) 09-07 交完 ③ 異源複驗（五格活體），wrapup 寫「可以收。⛔ 但最後一刀必須人工判，**我不替 dev 簽**」。
dev(calli) 09-09 來收，跑 `op=check --arg index=144`（dry-run）拿到：

```
已勾 0 / 未勾 3
可以勾的人：本單指名的 QA：summit
你是：calli ⇒ 🛑 無權
⛔ 本 op 沒有 qa_note= 代簽出口（resolve 有）
```

⇒ **①②③ 的勾只有 QA 能打，而 QA 把最後一刀交給了 dev。兩個人各持一半，兩邊都以為球在對方腳下。**

## 這不是 bug —— 兩條規則各自都對

- `op=check` 只認 QA：**勾驗收格是簽名行為**，非 QA 打的勾「對讀單的人看起來跟真的驗收一模一樣，
  而它沒有任何人負責」（守衛自己印的話，比我會寫的準）。
- `resolve` 的最後一刀留給人：本單的 commit 訊息永遠不會帶單號 ⇒ 閉環不會自己發生。

⇒ 缺的只是**沒有人被告知球在自己腳下**。

## 📌 接手判準（換人接手一定會撞到）

一張單掛著不動時，**「誰卡住」跟「卡在什麼」是兩個問題，而後者常常是空的**：
1. 先跑 `op=check`（**dry-run，零寫入**）—— 它會直接印出「可以勾的人」與「你是誰」。
   那一行比任何留言都便宜，而它常常就是答案。
2. 兩則 wrapup 都寫「可以收」而狀態沒動 ⇒ **不要再等表態，去查權限分佈。**
3. ⛔ 而查出來不在自己權限內時，**不要走 `resolve --arg qa_note=` 代簽繞過去**：
   那出口存在且是設計好的功能，但簽名的價值全在「不是同一隻手」那一點上
   （@summit 2026-09-04 TASK-0118 血證：代簽本身可以是對的，用一句錯的定語去代簽
   就是在時間線上留一筆看起來有出處的假帳）。
   ⇒ 正解是**把球明確交出去並說出「球在你那裡」**，不是自己補簽。
