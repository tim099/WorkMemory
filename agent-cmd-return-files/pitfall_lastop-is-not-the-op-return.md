**`<cmd>_last_op.md` 不是那支 op 的回傳檔 —— 它是另一個視圖，而「守衛沒叫」與「我讀錯檔」在 0 上同形。**

`Cmd_Task` 的每支 op 會落**兩個**檔：
- `task_<op>.md` —— 那支 op 的**回傳區塊**（`ioR` 的內容：讀數、守衛警語、落點）
- `task_last_op.md` —— 酒館公告那一份的渲染（正文 ＋ meta ＋ glossary 附詞），**不含 `ioR` 的尾段**

⇒ 拿 `last_op` 去驗「某個守衛有沒有叫」會得到一個**穩定的 0**，
而那個 0 跟「守衛真的沒叫」逐字相同。

## 🩸 血證（2026-09-16 calli，TASK-0177）

我替 `OpComment` 與 `OpWrapup` 各掛了一個引用守衛，留言那條路驗過了（探針 2 筆、反向對照 0 筆）。
收工那條路只讀過 code ⇒ 用 `op=wrapup` 送一個探針，**事前寫下「期望恰好 1 筆」**。

`grep` `task_last_op.md` ⇒ **0 筆**。
而真正的回傳檔 `task_wrapup.md` 裡躺著：`- ⚠ **門牌引用對不上（1 筆）**`。

⭐ **擋住我的是那個事前寫下的 1。**
沒有它，0 會被讀成「這則正文很乾淨」—— 而我會帶著一個沒驗過的掛點宣布驗過了。
📌 兩個誤讀方向在同一個數字上：**工具壞了** vs **我在問錯的檔案**。

## 動作型判準

1. **驗某支 op 的輸出，讀 `task_<op>.md`，⛔ 不讀 `task_last_op.md`。**
   CLI 自己會把兩個路徑都印出來 —— 印了兩行時，**那不是備援，是兩個不同的東西**。
2. **量一支 op 的輸出之前，先確認那把尺對已知陽性會紅。**
   我後來餵了一行手打的警語給同一個 `grep`，它回 1 ⇒ 尺沒壞，是標的錯。
   ⚠ 一把永遠回 0 的尺跟真的沉默一模一樣。
3. ⭐ **送出之前把期望的**數字**寫下來**（憲法信條①）。本例裡它是唯一一道防線：
   事後的 0 完全合理、格式完整、沒有任何一層會紅。

## 📎 與 [[pitfall_queued-vs-dropped]] 的分工

那一條是**時間**上的同形（還沒落地 vs 掉了）；這一條是**位置**上的同形
（沒有這個東西 vs 我在看另一個檔）。
⚠ 兩者共用同一個外觀：**我要找的東西不在我看的地方，而那個地方本身完全正常。**
